# Windows 모델 변경 토큰

NTFS에서 연속으로 닫힌 같은 크기의 쓰기에도 파일의 수정·변경 시각이 같게 반환되는
실행을 확인하였다. 시각만으로 모델 캐시를 식별하면 해당 쓰기를 놓칠 수 있다.

Windows Native 제공자는 파일을 식별할 때 `FSCTL_READ_FILE_USN_DATA`의 최근 변경
순번도 읽는다. V2·V3 레코드를 지원하며 파일 본문을 다시 읽지 않는다. 제공자 자신의
미리보기 메타데이터 게시 전후에는 시각과 순번을 함께 정규화한다. 외부 쓰기는 같은
크기·복원한 mtime이어도 새 순번으로 구별하고, SQLite WAL의 순번도 포함한다.
공개 API는 여전히 불투명 문자열 토큰을 반환한다.

Python 어댑터 회귀 검사는 미리보기 전후 토큰 보존과 64회의 실제 외부 덮어쓰기·mtime
복원마다 토큰 변경을 확인한다. 모델 파이프라인 캐시·모델 해시 재사용 검사는 이
설치된 제공자를 사용하여 다시 실행한다. 변경 저널을 제공하지 않는 파일 시스템은
기존 시각 기반 경로를 사용하며 이번 실행 증거는 이 머신의 NTFS에 한정한다.

[Microsoft의 파일별 변경 순번 계약](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_read_file_usn_data)을 따른다.
