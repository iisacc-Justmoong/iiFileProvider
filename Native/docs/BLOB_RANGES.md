# BLOB 범위 입출력과 배치 비교·교체

Native 0.11.0은 SQLite 실행·핸들을 공개하지 않고 큰 값의 일부를 읽고 쓰는
동기 C++23 경계를 제공한다. 연결·문장 작업은 기존과 같이 한 실행 영역에서
직렬화하며, 호출 동안 빌린 입력 바이트는 안정적으로 유지한다. 새 API는 문서·
픽셀·타일·상위 SDK를 알지 않는다. 공개 Database/Statement/Transaction 배치와
기존 Code 값, dylib ABI 0.5를 유지한다. 충돌 Code는 열거 끝에 추가한다.

## 범위 읽기

`read_blob_range(table, column, rowId, offset, count)`는 main 데이터베이스의
해당 값에서 요청한 바이트만 반환한다. 명시적 트랜잭션 밖에서도 읽을 수 있다.
끝 위치의 빈 범위는 유효하며, 범위를 넘는 offset/count와 정수 오버플로는 거부한다.
요청 크기는 연결의 값 크기 한도를 넘을 수 없다. SQLite가 incremental BLOB으로
열 수 있는 BLOB/TEXT 값에 적용하며 수치·NULL·누락된 행은 거부한다.
식별자는 SQL 문장에 삽입하지 않고 SQLite의 식별자 인자로 전달한다.

## 배치 비교·교체

`BlobRangePatch`는 바이트 offset과 같은 길이의 before/after span이다.
`compare_exchange_blob_ranges`는 명시적 SQL 트랜잭션 안에서만 호출한다.
쓰기 가능한 연결과 `Transaction::begin(database, true)`를 권장한다. 이 함수가
바깥 트랜잭션을 커밋하지 않는다. 읽기 전용 연결에서는 쓰기를 거부한다.

범위 순서는 자유롭고 비어 있지 않은 범위끼리 중첩할 수 없다. 모든 범위와 before를
검사한 뒤에만 쓰기를 시작한다. 잘못된 두 번째 범위나 이전 바이트 불일치는 앞의
범위도 쓰지 않는다. 불일치는 `Code::conflict`이다. 같은 길이를 유지하며 실제로 다른
연속 바이트만 기록한다. `BlobPatchStatistics`는 비교한 바이트와 기록한 바이트 수를
반환하며 페이지·저널·인덱스 비용을 나타내지 않는다. 무변경은 기록 바이트가 0이다.

배치 메타데이터와 비교 바이트의 합계는 각각 연결의 값 크기 한도 안에 있어야 하며,
범위 수는 65,536개 이하이다. 빈 범위는 바이트를 차지하지 않는다. 빈 배치도 연결·
식별자·행·명시적 트랜잭션을 검증한다. 입력 span이나 쓰기 명령을 보관하지 않는다.

실제 쓰기는 내부 savepoint로 묶는다. 늦은 I/O 오류 등에서 savepoint를 되돌리고,
이를 복원할 수 없으면 바깥 트랜잭션을 롤백한다. 복원 결과도 확정할 수 없는 연결은
폐기하여 뒤의 Native 호출에서 부분 변경을 커밋할 수 없게 한다. SQLite 자체의
전원 차단·장치 내구성은 기존 트랜잭션 계약에 속한다. 오류를 성공으로 바꾸지 않는다.

## 스트리밍 체크섬

`blob_sha256(table, column, rowId, maximumBytes)`는 전체 값의 SHA-256을
32바이트 배열로 반환한다. 전체 BLOB을 C++ 값에 복사하지 않고 고정 크기 버퍼와
기존 SHA-256 구현을 사용한다. maximumBytes는 호출자가 반드시 지정한다.
값이 이를 넘으면 읽기 전에 거부한다. 열려 있는 BLOB 읽기 수명 동안 같은 SQLite
읽기 시점을 유지하며, 기존 트랜잭션 안에서는 자신의 아직 커밋하지 않은 값도 읽는다.
이는 전체 바이트를 해시하는 CPU·I/O 비용을 없애는 기능이 아니다.

## 검증과 채택 경계

계약 검사는 경계·빈 값·NUL·정렬되지 않은 구간·중첩·잘못된 두 번째 구간·충돌,
바깥 롤백·커밋·재열기·같은 이름의 중첩 savepoint·쓰기 제한 열의 늦은 오류,
TEXT·읽기 전용·한도·체크섬을 검사한다. 일반 빌드의 C++ 할당
실패 주입과 별도 ASan/UBSan 검사를 구분한다. 큰 BLOB 검사는 8K ARGB32 자산과
같은 256 MiB 값을 사용하고 SDK C++ 할당 규모를 기록한다. 이 계측은 SQLite C
할당자나 프로세스 RSS를 측정한 것이 아니다.

이 단계는 DocumentFile을 새 경계에 연결하거나 작업 파일을 타일별 체크섬 형식으로
전환한 것이 아니다. 전체 문서 임시 사본·자산 인코딩·전체 자산 해시 비용을 제거하는
후속 캔버스 트랜잭션에서 이 경계를 채택한다. 앱·기기 검증과도 구분한다.

설치본은 Native README의 `docs/` 링크와 기존 데이터베이스 안내의
`../Native/docs/` 링크도 해석되도록 같은 원본 문서 집합을 각 진입점의 상대 경로에
공급한다. 검증 시 원문/JSON 동일성과 새 계약 링크의 실제 파일 존재를 함께 확인한다.
