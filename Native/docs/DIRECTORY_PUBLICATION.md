# 네이티브 디렉터리 원자적 게시

이 API는 Native 0.11.1부터 제공한다. 기존 0.11.0 설치본에는 이 심볼이 없으므로
소비자는 최소 0.11.1 패키지를 요구해야 한다.

`<iiFileProviderNativeDirectory.h>`의 `publishDirectoryExclusive(stage, destination)`은
같은 실제 부모 아래의 준비된 일반 디렉터리를 새 이름으로 원자적으로 이동한다.
소스가 심볼릭 링크이거나 일반 디렉터리가 아니면 거부한다. 출력이 파일·디렉터리·
심볼릭 링크인 경우와 다른 부모인 경우에도 실패하며 기존 내용과 준비 디렉터리를
보존한다. 다른 프로세스가 동시에 같은 이름을 게시해도 운영체제의 배타적 이름
변경으로 기존 대상을 덮어쓰지 않는다. 실패 결과는 `PublishResult`의 진단 접미사와
메시지로 확인한다. 호출자는 게시가 성공하면 새 경로를 소유하고, 실패하면 준비
디렉터리의 정리를 책임진다.

`TemporaryDirectory`로 준비한 경우 성공 직후 `release()`로 이전 이름의 정리
소유권을 내려놓는다. 그러면 다른 작업이 그 이름을 다시 만들어도 소멸자가 새
디렉터리를 삭제하지 않는다. 실패 시에는 소유권을 유지해 준비 디렉터리를 정리한다.

현재 macOS, Linux의 `renameat2`, Windows의 배타적 이동을 사용하며, 배타적
디렉터리 이름 변경을 사용할 수 없는 플랫폼이나 파일 시스템에서는 `unsupported`로
실패한다. 이 경우 테스트는 준비 디렉터리가 보존되는지 확인한다.
다른 디렉터리 또는 볼륨으로 복사하는 대체 동작은 제공하지 않는다. 호출자는 게시
중 준비 디렉터리를 다른 코드가 바꾸지 않도록 소유권을 유지해야 한다. API는
디렉터리 내부 데이터의 별도 내구성 동기화를 보장하지 않는다.

`iiFileProvider.Native.Device`는 정상 게시, 기존 파일·디렉터리와 심볼릭 링크,
다른 부모, 두 작업의 동시 게시와 양쪽 원본 보존을 검사한다. 테스트를 빌드하는
것과 각 운영체제에서 실행하는 것은 별개의 증거이다.
