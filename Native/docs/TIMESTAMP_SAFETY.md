# 네이티브 저작 시각의 할당 실패 경계

Native 0.10.1은 고정 ISO-8601 시각 형식의 어휘 검사를 문자 단위로 수행한다.
YYYY-MM-DDTHH:MM:SS, 선택적인 1..3자리 소수 초, Z 또는 부호 있는 HH:MM 오프셋을
검사한 뒤 기존 chrono 날짜·시각·오프셋 검증과 UTC 밀리초 정규화를 적용한다.
형식 검사에 지연 초기화 정규식을 구성하거나 소수 초 문자열을 임시 할당하지 않는다.

캔버스 이력의 할당 실패 주입에서 첫 recordChange 호출의 정규식 초기화에 진입한
프로세스 충돌을 확인했다. 고정 형식은 동적 정규식이 필요하지 않으므로 이 초기화
의존성을 제거한다. 다른 계정·URI 정규식 검증의 지원 범위를 변경하지 않는다.

저작 덤프 재구성의 임시 JSON DOM에서도 할당 예외 처리 중 종료되는 경로를
재현했다. 고정된 스키마 3의 캐시는 검증된 프로필 JSON과 이스케이프한 문자열로
완전히 준비한 뒤 교체한다. 기존 키 순서·null·리비전 문자열·배열 순서와 최대 크기
계약을 유지하며, 재구성 실패는 기존 캐시를 바꾸지 않는다.

`Native.TimestampAllocation`은 첫 호출부터 C++ 할당을 한 위치씩 실패시키고,
실패한 변경의 저작 리비전·덤프 보존과 성공한 변경의 정확한 UTC 값을 검사한다.
잘못된 구분자·소수 길이·오프셋·날짜와 유효한 윤년도 검사한다.
할당 실패 주입은 일반 빌드에서 수행하고, 표준 Native 저작 정보 검사는 별도
ASan/UBSan 구성에서도 실행한다. 계측 범위와 실제 결과는 단계별 증거에 기록한다.

공개 구조체 배치와 dylib ABI 0.5는 유지한다. 설치 소비자는 같은 의존성 조합의
새 헤더·라이브러리를 사용하고, 기존 앱·키트와 이전 증거는 보존한다.
